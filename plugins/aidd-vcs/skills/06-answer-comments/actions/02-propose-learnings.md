# 02 - Propose Learnings

Propose the feedback that should outlive the pull or merge request, and post the summary.

## Input

The threads answer-comments replied to, the ones it handed over, and prior resolved review threads and summary.

## Output

One summary comment on the pull or merge request, shaped by [comments-summary-template.md](../assets/comments-summary-template.md) and kept up to date across runs.

## Process

1. **Keep.** Sort the feedback per [learnings.md](../references/learnings.md), including prior resolved threads.
2. **Fill.** Fill `comments-summary-template.md` from the review history, retaining settled counts and learnings across runs.
3. **Post.** On the first run, post the summary with its marker. On later runs, edit only a summary carrying the marker and authored by the current account. If several match, stop and ask which to update. If none matches but an unmarked comment by this account opens with `## Review comments`, ask before adopting it or posting another summary; otherwise post one.
4. **Offer.** If there are learnings, propose running the skill that captures durable project learnings with this summary as input.

## Rules

- Keep learnings as proposals; write no rule, memory or skill.
