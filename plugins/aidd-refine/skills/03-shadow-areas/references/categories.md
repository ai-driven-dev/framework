# Categories

The category of a gap, in report order. A gap takes the first that fits.

| Category | The source | Example |
| --- | --- | --- |
| contradiction | states two things that cannot both hold, quoted both | "Guests can check out" and "checkout requires an account" |
| missing actor | leaves out who performs, decides or is affected | an approval with no approver role |
| missing dependency | relies on a system, data or step it does not name | SMS sent with no provider named |
| missing failure mode | gives success but not failure | a charge with no declined-card case |
| missing edge case | covers the usual input but not a boundary or exception | a 10 MB limit with no rule at exactly 10 MB |
| ambiguous term | uses a word two builders would read two ways | "respond quickly" with no threshold |
| missing acceptance criterion | states a requirement no test could pass or fail | "results must be relevant" |
| unstated assumption | needs a condition it never writes | checkout that assumes a signed-in user |
