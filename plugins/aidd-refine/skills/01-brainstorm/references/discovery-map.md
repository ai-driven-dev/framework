# Discovery Map

Use this map to decide what to explore next.

Go down the list and take the first point still unclear. Ask with one of its angles, only when it fits.

In the first round, a vague idea (a topic or a solution only) starts at the first point with one example. A precise one (most points there) starts at its single riskiest gap.

## Points

| Means | Angle |
| ----- | ----- |
| actor, pain, desired change | who benefits, what changes, why now? |
| trigger, steps, visible behavior | one case that should work, one that should not |
| non-goals, smallest useful slice | the smallest useful version, where this stops |
| inputs, state, API, permissions, invariants | dependency, platform, cost, latency, security, ownership |
| acceptance, metric, observable done signal | what proves it works, what fails the idea? |
| edge case, dependency, rollout, operational risk | empty, duplicate, concurrent, stale, missing, hostile, partial |

## Beyond the list

Open one only when it can change a point above.

| Branch | Use for |
| ------ | ------- |
| Tradeoff | technical or operational tradeoff |
| Codebase boundary | codebase boundary or ownership |
| Data contract | type, schema, service, or data contract |
| Change path | change path, compatibility, migration, or rollout |
