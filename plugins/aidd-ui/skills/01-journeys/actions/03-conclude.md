# 03 - Conclude

Leave journeys and wireframes that validate, and tell the user what follows.

## Input

The engine and the files written.

## Process

1. Validate per [engine](../references/engine.md).
2. Fix each error line as its `=> fix` says.
   - Only in the folders this skill writes.
3. Validate again per [engine](../references/engine.md), and repeat until none is left there.
4. Keep the `warning` lines.
5. Keep the errors the [engine](../references/engine.md) says another skill owes.
6. Ask the person to agree with each journey still proposed.
   - Name each by its title, with its steps in a few words.
   - Ask for the set at once when there are few.
   - Offer two answers: agree, or change.
   - Wait for the answer.
7. The engine publishes each journey they agree with, per [engine](../references/engine.md).
   - If they want a change, read [write](02-write.md) first, then ask again.
   - Leave a journey with no answer as it is.
8. Validate again per [engine](../references/engine.md), and fix as in steps 2 and 3.
9. Write the showcase per [engine](../references/engine.md), in the language the person writes in.
10. Reply, in plain words, per the transversal rules:
   - the journeys and wireframes written or raised
   - the journeys agreed, and those still awaiting their agreement
   - how to open the showcase, once
   - the single next step: set the brand
   - leave out the review wait and any warning count
   - an error another skill owes is not a failure: leave it out

## Output

The reply to the user.
