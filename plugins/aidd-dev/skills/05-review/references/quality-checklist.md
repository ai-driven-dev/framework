# Quality checklist

Apply relevant items alongside project review rules; justify non-applicable items.

- [ ] **Duplication:** each fact or responsibility has one canonical home.
- [ ] **Consistency:** components, names, documentation, and project conventions agree.
- [ ] **Simplicity:** complexity serves the need; abstractions have a current use.
- [ ] **Residue:** obsolete code, debug leftovers, silent TODOs, and placeholders are absent.
