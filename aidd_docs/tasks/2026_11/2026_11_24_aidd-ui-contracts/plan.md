## Impact

| Category      | Verdict and evidence | Handled in |
| ------------- | -------------------- | ---------- |
| runtime       | each skill ships about 485 KB of generated engine, six copies in the plugin | 1 |
| regression    | the flat install puts skills and hooks under different tool folders for Codex (`.agents/skills`, `.codex/hooks`), so a skill reaching `../../hooks` breaks there | 2 |
| architecture  | the hook keeps the code-literal check and its session baseline, which no contract can hold: a turn that writes only code forms no unit under `aidd_docs/ui` | 3 |
| documentation | each skill's `references/engine.md` loses its install table | 2 |

## Rules

| Rule | Why it applies |
| ---- | -------------- |
| A skill never links outside itself (`architecture.md`) | the tree ships both flat and as a marketplace |
| A template and its contract move together (`CLAUDE.md`) | phase 3 adds contracts beside the skills |
| One Stop entry per plugin (`docs/ARCHITECTURE.md`, Hooks) | OpenCode and Kilo silence a second one |

## Decisions

| Decision | Why |
| -------- | --- |
| The whole engine is copied, byte for byte, into `scripts/aidd-ui/` of every skill | a per-command closure saves 12 %, since every skill runs `showcase`, `bump` and `validate`; byte-identical copies need no path rewrite |
| The source stays in `plugins/aidd-ui/hooks/` | the hook runs it there; the copies are generated by `run.cjs --fix` and checked by it |
