# Hook contract

The contract every hook the framework ships follows. Phase 14 moves its durable part into `docs/ARCHITECTURE.md`. A user's own hooks, generated by `aidd-context:08-hook-generate`, are not bound by it.

## 1. What a hook is for

A hook adds determinism where a model drifts. It checks mechanical rules only: a rule a script decides with no judgment, reading as many files as it needs. A rule that needs judgment belongs to the skill's check and to CI.

## 2. Levels and moments

A level is what the finding demands; a moment is when the artifact is final.

| Level | Effect | Mechanism | Used when |
| --- | --- | --- | --- |
| 1. Inform | the model reads the finding and decides | `additionalContext` | the rule is certain but a deviation can be legitimate |
| 2. Require | the model must fix before going on | `decision: "block"` with `reason` | the rule is certain, measured with no false positive on real data, and the fix is local |

| Moment | Event | For |
| --- | --- | --- |
| After the write | PostToolUse | an artifact final in one write: a memory file, a frontmatter |
| At the turn end | Stop, once per turn, scoped to what the turn reached | an artifact final only after several writes: a design-system change across record, render and tokens |

No level stops a write: PreToolUse sees an `Edit` fragment, not the final file, and would block drafts. A rule never fires at a moment where its artifact is still in progress.

### Placing a gap

```
1. Needs judgment?                       yes => no hook
2. When is the artifact final?           one write => after the write; several => at the turn end
3. False positives on real data?         some => level 1
                                          none => level 2 if the fix is local, else level 1
```

## 3. Events

| Event | Use |
| --- | --- |
| SessionStart | keep a generated state true, silently: its text never reaches the model on OpenCode or Kilo |
| PostToolUse | check what this write produced |
| Stop | check what the turn reached, for multi-write artifacts; asks once, guarded by `stop_hook_active` |

PreToolUse is native on all six hosts, but the OpenCode and Kilo bridges do not replay it, and nothing in this contract needs it. UserPromptSubmit and SessionEnd are out of the contract. aidd-telemetry is the stated exception: observing a session is its job.

## 4. Rules

1. **Owner scope.** A hook checks the paths its plugin owns and exits before reading anything else. aidd-context also owns the layout of `aidd_docs/`: which plugin owns which folder, and a file out of its place. It never checks the content of another plugin's folder.
2. **One neutral interface.** A hook reads its event and answers through `hooks/lib/host.cjs` (`readEvent`, `answer`, `continueTurn`), never a host's payload directly. The CLI puts each tool's adapter there at build time (section 6).
3. **Findings only.** What this write or this turn produced, never the project's standing errors. Every error of a written file, one line each; errors of files the change reached, grouped by rule and fix; then the warnings, capped at 10: the highest count both Haiku and Qwen fixed with no finding missed and no content lost (`measure.md`):

```
<plugin>: <n> errors, <m> warnings
<file>[:<line>] <rule> ["<excerpt>"] => <fix>
<rule> ×<count> in <folder>/* ["<excerpt>"] => <fix>
<file>[:<line>] <rule> warning <message> => <fix>
```

   Line and excerpt are optional: a missing section has neither. The group's folder is the file's dirname relative to the project root, with forward slashes on every OS. A group of one prints the plain error line, never `×1`. A group prints an excerpt only when every member has that same excerpt. Never "rerun this command": the line carries the fix. Silence when clean.
4. **One entry per concern.** `node ${CLAUDE_PLUGIN_ROOT}/hooks/<concern>.cjs hook|check|sync`; the same file runs by hand, from a skill and in CI with the same result. Everything it calls lives under `hooks/`.
5. **Node built-ins only.** CommonJS, `fs`, `path`, `os`. No dependency, no child process, no git, no network.
6. **Bounded.** A 5 s declared timeout; the work well under a second. Exit 0 on garbage, empty stdin or an unknown event; an internal failure answers nothing.
7. **Stateless, except a turn-end check.** A PostToolUse-only plugin keeps nothing. A plugin with a Stop check keeps one file per session listing the paths the turn wrote: `<os.tmpdir()>/aidd-hooks-<uid>/<plugin>/<session>`, folder `0700`, file `0600`, session id whitelisted `^[A-Za-z0-9_-]{1,128}$`, cleared at Stop, files older than 24 h swept at SessionStart without following a link. No mark, no Stop check: a turn that wrote nothing in scope costs nothing and never meets a standing error. A write appends each watched path it touched, one per line. A shell command appends the line `unknown`, its own line form, never an empty file, when it runs the plugin's engine, or when its text names a watched folder and matches a write form; any `unknown` line scopes the Stop check to the watched folders, known paths included. A read-only command marks nothing: agents read the watched folders in almost every turn, and marking reads blocked unrelated turns on standing errors (measured in aidd-ui, then reverted). Limit: a write the forms miss, such as `python -c`, is seen late, by the next write, the skill's check or CI, never lost.

## 5. Shared code

Three pieces every plugin uses live in one file, `hooks/lib/common-rules.cjs`, copied into each plugin and held identical by `scripts/check-hook-rule-copies.js`, until the CLI builds every distribution:

- `deadPaths(text, root)`: a backticked path that does not exist, the one rule every plugin applies to its own files;
- `isShellWrite(command)`: the shell write forms, a redirection other than `2>&1` or to `/dev/null`, `tee`, `sed -i`, `mv`, `cp`, `rm`, `touch`, `mkdir`, `patch`, `apply_patch`, `perl -i`, `find … -delete`, `git apply`, `git mv`, and the git subcommands that touch the working tree: `git checkout` except `-b`/`-B` with no path, `git restore` except `--staged` without `--worktree`, `git rm` except `--cached`, `git reset` with `--hard`, `--merge` or `--keep`, `git stash` bare or with `push`, `pop`, `apply`, `drop` or `clear`;
- `formatFindings(plugin, findings, options)`: the output of rule 3.

The Stop state file stays with the plugin that has a Stop check until a second plugin needs it.

## 6. What the CLI carries

| Concern | Where |
| --- | --- |
| Hook config per tool: destination, wrapper, event map, fields kept, root token | one descriptor per tool, `profiles/<tool>/`, data only |
| Merge and unmerge of one plugin's entries | one engine, used by every route that writes hooks |
| Payload in, answer out | one adapter per host in `cli/assets/hooks-runtime/`, same exports; the plugin tree ships Claude's as `hooks/lib/host.cjs`, and the build replaces it with the target's. The hook command never changes, no extra process runs, and nothing calls the `aidd` binary at run time |
| Adding a tool | one descriptor and one captured payload fixture; the contract test fails when either is missing |

A Codex or Copilot `apply_patch` becomes one event listing every file it touched. The event names its `host` and keeps the host's payload as `raw`, so a hook that needs a host field (aidd-telemetry tells Codex by `transcript_path`) still reads it.

Where a host does not deliver a level 2 answer to the model, its adapter answers at level 1 there.

## 7. Host facts

| Event | Claude Code | Codex | Cursor | Copilot | OpenCode | Kilo |
| --- | --- | --- | --- | --- | --- | --- |
| SessionStart text reaches the model | yes | yes | yes | yes | no | no |
| PostToolUse answer key | `hookSpecificOutput.additionalContext` | same | `additional_context` | top-level `additionalContext` | appended by the bridge | same |
| PostToolUse `decision: block` reaches the model | yes, as a blocking error naming the reason | yes | no, the model saw nothing (`decision` and `reason` only, no other key tried) | yes | yes, the bridge appends the reason to the tool result | same |
| Stop continues the turn | `decision: block`, yes; the second Stop carries `stop_hook_active: true` | same | `followup_message`, not run: `stop` did not fire in headless `cursor-agent -p` | `decision: block`, yes; same `stop_hook_active` | `promptAsync`: the prompt lands as a user message, the reply was not observed (headless `run` exits at idle) | `promptAsync`, yes: the model answered it |
| PreToolUse | native | native | native, mapped by the CLI | native | native, not bridged | native, not bridged |

Copilot accepts the nested hooks shape (`matcher` plus a `hooks` array), as the native tree ships it: a plugin installed from the native build fired SessionStart and PostToolUse, and expanded `${PLUGIN_ROOT}`. The flat shape in `.github/hooks/*.json` also fires, and needs `--trust-folder` in prompt mode.

Copilot's behaviour on a crashing PreToolUse hook is not stated by its official reference; untested.

## 8. Tests

| Test | Proves |
| --- | --- |
| Adapter fixtures | one captured payload per host and event goes in, the neutral event and the host's answer key come out |
| Contract test | each plugin's hook entry runs with each host's adapter on six hosts: right files, right answer key, exit 0 on garbage |
| Rule tests | each rule fails on its fixture and passes on the fix; each level 2 rule has zero hits on the four real banks |
| Copies check | every copy of the shared rule is identical |
| Host campaign | before merge: a finding reaches the model on the six hosts |
