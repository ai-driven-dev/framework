# Rule verification publication, 2026-10-12

The October 11 verification was published to [PR #979](https://github.com/ai-driven-dev/framework/pull/979) in two commits: `af582f2d` binds reproduction reads to validated descriptors; `f614eb61` adds official-contract guidance, independent YAML tests and the indexed evidence. The 238 archived file hashes were checked against the staged Git blobs before committing. Personal `.gitignore` changes and `.hermes.md` remain outside the commits. The framework CLI and production rule writer are unchanged.

On `f614eb61`, [CodeQL succeeded with zero annotations](https://github.com/ai-driven-dev/framework/runs/114641551998), confirming that the three previously reported filesystem races and seven unused-variable annotations no longer appear. Framework validation and the other CLI checks succeeded, but the [Windows job failed](https://github.com/ai-driven-dev/framework/actions/runs/38196784726/job/114641144794) in two new reproduction-security tests. Its aggregate CLI gate consequently failed as well.

The failure exposed a portability defect in the reproduction helper: missing `O_NOFOLLOW` silently became zero in the bitwise open flags, allowing a symlink read. The follow-up requires nonzero integer `O_NOFOLLOW` and `O_NONBLOCK` capabilities before any open; unsupported platforms refuse the read. This preserves the reproduction's safety boundary without substituting a pathname check vulnerable to replacement. POSIX-specific cases carry an explicit capability-based skip reason; a separate cross-platform test checks refusal before filesystem access when either capability is missing or zero.

The new guard test failed against the previous helper with `Unexpected filesystem I/O`, then passed after the guard was added: [RED](publication-tests/guard-red.tap), [GREEN](publication-tests/guard-green.tap). All nine targeted tests pass on macOS without skips. Six simulated invalid capability combinations perform zero filesystem calls; the actual helper's refusal is also asserted when the running platform lacks these protections. The POSIX cases do not count as executed on unsupported platforms.

The October 11 reports and indexed receipts describe their original candidate and remain unchanged. This follow-up does not establish native Windows AI-tool execution or remove the documented Copilot automatic-loading and Cursor quota limitations. Current publication status and subsequent CI results are available in the PR.
