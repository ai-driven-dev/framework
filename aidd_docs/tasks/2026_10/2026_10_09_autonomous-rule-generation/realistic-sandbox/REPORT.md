## AGENTS.md and native scopes

Codex and OpenCode receive the rule body once in a signed `aidd_rules` contribution in root AGENTS.md, together with explicit scope prose. Their Markdown scope is model guidance, not a native glob filter or an include directive. Claude, Cursor and Copilot additionally receive their documented native scoped formats. The official [Codex AGENTS guide](https://learn.chatgpt.com/docs/agent-configuration/agents-md) describes discovered instruction files and root-to-working-directory precedence; it does not document expanding Markdown links as includes. This implementation therefore embeds the body rather than relying on such expansion. An [actual published AGENTS.md](native-evidence/opencode/examples/published-AGENTS.md) and the [initial](native-evidence/opencode/examples/initial-consumer.ts), [updated](native-evidence/opencode/examples/updated-consumer.ts) and [post-delete](native-evidence/opencode/examples/post-delete-consumer.ts) application code show the concrete result.

OpenCode's real installed AIDD memory hook runs at session start and owns `aidd_project_memory`. It legitimately regenerates that block from real memory files, changing the initial 378-byte AGENTS.md to 304 bytes. Independent review confirms that exact transformation and unchanged bytes outside the memory block. This is not writer corruption and does not support claiming whole-file equality against the initial pre-hook fixture. A second native author/delete pair with the hook still active preserves the converged 304-byte AGENTS.md exactly. The original unrelated native rules and architecture memory retain their hashes.

Claude's official [memory documentation](https://code.claude.com/docs/en/memory) explains path-matched rule loading and the settings-source condition. [Cursor rules](https://cursor.com/docs/rules), [Copilot instructions](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-custom-instructions), [OpenCode V2 instructions](https://opencode.ai/v2/docs/instructions/) and [skills](https://opencode.ai/v2/docs/skills/) were checked against the actual installed layouts. Behavioral proof is kept distinct from captured native rule bodies and from earlier mock-provider model-input captures.
